1. 什么是离屏渲染

1.1 正常渲染流程（On-Screen Rendering）

在正常渲染中，GPU 接收渲染指令后，直接将结果写入帧缓冲区（Frame Buffer），整个过程是单向的”一笔画完”。

✅ 关键特征：GPU 只操作一个缓冲区，数据单向流动，无需回读。

1.2 离屏渲染流程（Off-Screen Rendering）

当 GPU 发现某些效果无法在一个 Pass 中完成时（例如需要对所有子图层合成后再做裁剪），就必须先在一个**独立的离屏缓冲区（Offscreen Buffer）**中渲染中间结果，然后再合成回帧缓冲区。

⚠️ 红色部分就是离屏渲染的额外开销：创建缓冲区 → 上下文切换 → 渲染 → 切回 → 合成。

2. 为什么离屏渲染慢 —— 三大根因

2.1 根因一：GPU 上下文切换（Context Switch）

GPU 在渲染时有一个”当前渲染目标”（Render Target）的概念，类似于 CPU 的线程上下文。

类比理解 🎨：

想象你在画一幅画（正常渲染），突然需要在另一张纸上先画一个部件，画完再剪下来贴回原画（离屏渲染）。你需要：

  1. 放下当前画笔和颜料（保存状态）
  2. 拿出新纸铺好（创建离屏缓冲区）
  3. 画完部件（离屏渲染）
  4. 收起新纸，重新铺好原来的画（恢复状态）
  5. 把部件贴上去（合成）

每一步”收拾桌子”的动作就是 上下文切换 的开销。

2.2 根因二：额外的内存开销和带宽消耗

对比项 正常渲染 离屏渲染
内存写入次数 1 次 2 次（写 Offscreen + 写 Frame）
内存读取次数 0 次 1 次（读回 Offscreen）
额外内存占用 无 Offscreen Buffer（最大屏幕像素 × 2.5）
总带宽消耗 1W 2W + 1R = 3 倍

⚠️ iOS 设备的 GPU 和 CPU 共享内存带宽，带宽资源非常宝贵！额外的读写操作会严重挤占其他渲染任务的带宽。

2.3 根因三：破坏 TBDR 优化（iOS 特有，影响最大！）

Apple GPU 采用 Tile-Based Deferred Rendering（TBDR） 架构，这是理解离屏渲染在 iOS 上为何特别慢的关键：

TBDR 的核心优势：渲染在 GPU 的片上 SRAM 中完成，SRAM 的速度比主内存 DRAM 快 10~100 倍，而且极大减少对主内存的读写（省电、省带宽）。

离屏渲染如何打破这一优势：

💡 一句话总结：离屏渲染迫使 GPU 绕过高效的 TBDR 管线，从”在超快的片上缓存工作”退化为”直接操作慢速主内存”，效率大幅下降。

8. 总结

离屏渲染慢的三大核心原因

核心结论

  1. 离屏渲染的本质：GPU 无法在一个 Pass 中完成某些复合效果，不得不借助额外的缓冲区做多步合成。
  2. 慢的根因：上下文切换 + 额外带宽 + 破坏 TBDR（iOS 上影响最大）。
  3. 单个离屏渲染可能不明显，但在列表滚动等高频场景下大量触发时，帧时间轻松超过 16.67ms，造成肉眼可见的卡顿。
  4. 优化原则：能避免就避免，避不开就用 shouldRasterize 缓存，或在 CPU 端预处理。
