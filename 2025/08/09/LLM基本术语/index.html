LLM 基本术语入门

本文提供一个尽可能无门槛的大语言模型应用开发入门，并对齐术语概念。

大语言模型 Large Language Model

LLM 是一种基于深度学习的自然语言处理模型，能够理解和生成自然语言文本。它的能力主要来源于大规模的预训练
数据和模型架构。

在 2017 年，Google的一篇《Attention is All You Need》发明了Transformer架构， 2022 年 12 月，OpenAI推出的GPT
3.5 正式宣告了大语言模型狂潮的开始。

让大语言模型长出一双手： Function Calling

早期，朴素的工具调用方式

在早期的LLM应用开发过程中，涌现出了期望 LLM 调用传统计算机程序的需求。
我们举个最简单的例子：小红想做一个属于自己的LLM数学助手，但LLM并不能够进行真正意义上的数学运算。
于是便产生了一个解决方案：利用提示词，要求 LLM 以格式化方式输出内容，然后利用计算机程序解析 LLM 输出，执
行相应操作，并将结果继续喂给LLM或是呈现给用户。

这种形式在早期大行其道，但缺点实在太多：
  1. 强烈依赖System Prompt，也就是提示工程（Prompt Engineering），早期模型智商不高，必须编写足够精确的
    Prompt才能优雅控制模型行为。
  2. 即便写了非常好的System Prompt，模型的指令遵循性仍是无法确定的，毕竟其内部基于概率模型，不能做到像
    典型计算机程序般说一不二。
  3. 失去流式输出特性：在输出结束前，你无法知晓一段消息应当展示给用户，还是应当作为某种程序的输入。
  4. 严重缺乏标准化。几乎你能在每个地方看到不同的设计，这说好听了是百花齐放，说难听了就是技术/学术界的割
    裂。

现代，Function Calling

为了解决前文提到的需求与问题， OpenAI 于 2023 年 6 月 13 日在其 GPT-4 和 GPT-3.5 Turbo 模型中引入了大名鼎
鼎的 Function Calling

Function Calling作为一种机制，使得大型语言模型（ LLM ）能够调用外部函数或 API ，标志着 LLM 与外部世界连接
方式的重大进化，使得模型能够在生成回答的过程中，智能地选择调用外部函数，并以结构化的形式返回信息，从而
增强了模型的能力和应用范围。

Function Calling 的引入，使得开发者能够更可靠地将 GPT 的能力与外部工具和 API 相连接，推动了大模型应用的快
速发展。

LLM + Function Calling = Agent

在前文中，我们已经讨论了大型语言模型（LLM）和函数调用（Function Calling）的基本概念及其演变。接下来，我
们将深入探讨 Agent （智能体） 的概念，特别是它与 LLM 和 Function Calling 的关系。

Agent 是一种能够感知环境、进行决策并执行动作的智能实体。在人工智能领域，Agent 通常具备以下核心能力：

在 LLM 的基础上， Agent 可以通过调用外部工具、访问数据库或与其他系统交互，完成更复杂的任务。

例如，在旅游规划场景中，Agent 可以根据用户的需求，查询天气、预订机票、安排住宿等，形成一个完整的服务流
程。

如下，是LLM，Function Calling, Agent的关系：

LLM 提供自然语言理解和生成能力 Agent 的“大脑”，负责理解用户需求和生成响应

Function Calling 使 LLM 能够调用外部函数或 API 执行操作 Agent 的“手脚”，用于执行具体任务

Agent 具备感知、决策和执行能力的智能实体 LLM + Function Calling，实现自主任务执行

因此，Function Calling 是构建 Agent 的基础能力之一，Agent 通过 Function Calling 调用外部工具，实现任务的执
行。

MCP

MCP （ Model Context Protocol ） 是由 Anthropic 于 2024 年 11 月推出的一项开放标准，旨在为大型语言模型
（ LLM ）与外部工具、数据源之间的交互提供统一的连接协议。

但就目前（ 2025 年 7 月）的进展而言，MCP暂时只是一个使得 Function Calling 更加容易的辅助工具。诚然，对于toC
市场而言，用户可以在自己的Chat客户端上通过配置MCP服务使得自己手头的AI工具「张手」，无需编程经验即可享
受MCP生态。但对于经历过上述LLM应用发展过程的开发者而言，MCP目前解决的问题主要是使得 Agent 开发过程中
的 Function Calling 集成更加容易，我们可以通过简单几行配置，快速地集成第三方开发的Function，这个Function
与传统的程序内建Function唯二的区别是，其可以是异构的，也不关心其是部署在本地（ IPC ）还是远端（ RPC ）。

不少同学对MCP产生了误解，认为MCP是Agent开发的基础。

但实际上，MCP 的主要目的在于解决当前 AI 模型因数据孤岛限制而无法充分发挥潜力的难题，并非发明了大语言模
型调用典型计算机程序的功能。MCP 更像是为AI 应用提供了一个更规范的连接万物的接口标准。

我们必须消除对 MCP 的误解，才能够更好地开发更多的Agent机器人。

OpenAI格式API

大家都知道，OpenAI是世界上最火的大语言模型，其API也就逐渐地就成为了事实标准：所有的大语言模型，都会额
外提供一套OpenAI格式的API，并且积极维护，以此实现与现有的程序无缝连接。

也就是说，对于任何的大语言模型，我们都可以直接利用OpenAI官方的SDK进行开发，也只需要学习OpenAI格式的
输入（Message, Function Calling等）
