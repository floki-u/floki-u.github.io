git log 查看下当前分支的提交记录 commit id,还有head指针，他指向最新的提交。我们可以通过修改head指向去回退版本

git reflog可以帮助你查看本地代码库中的所有操作记录，包括所有分支、提交、合并和重置操作。

当你误删分支、提交、文件等操作时，你可以使用git reflog命令找回你误删除的内容

在本地更改的一些文件，但是还没add到暂存区，想要退回到原始样子，就是丢弃我们本地工作区的这些改动-> 用git checkout – xx(想还原的文件)

如果add之后，添加到暂存区了，但是不想要这个修改，也就是回退add操作，可以用

git reset HEAD 文件名 这样被add的文件修改就从暂存区退出来了，我们本地再修改好了再去add

如果commit 之后把暂存区的修改提交到了本地仓库上，我们git log就能看到，此时本地仓库的提交是领先于远程的，本地的是5e44那一笔，而远程仓库或者说别人只能看到cf9c那一笔

那么此时如果commit有误，想要回退到之前的样子，那么用

git reset –hard commit_id 就是实现了head指针去指向旧的提交版本，相当于就是把本地仓库不想要的提交给回退了，但其实5e44那一笔提交还是在的，只是我们把head指针移动了一下，并没有做删除操作

因为没有做删除操作那么如果我又想回到5e44那一笔的话，我们可以git reflog 能看到之前的操作记录，然后再git reset –hard 5e44 ，这样就又回去了

如果push到了远端，怎么回退

如果期间没有别人的提交，那么我们可以利用上面的方式做本地做回退 ，回退完之后因为本地代码落后于远端，push不上去，这时候就得push -f 强制推送

工作目录 vs 暂存区 git diff —查看文件在工作目录与暂存区的差别。如果还没 add 进暂存区，则查看文件自身修改前后的差别。也可查看和另一分支的区别。 git diff

- 暂存区 vs Git仓库

git diff –cached

— 意义：表示查看已经 add 进暂存区但是尚未 commit 的内容同最新一次 commit 时的内容的差异。 也可以指定仓库版本：

git diff –cached

- 工作目录 vs Git仓库 git diff 意义：查看工作目录同Git仓库指定 commit 的内容的差异。 =HEAD 时：查看工作目录同最近一次 commit 的内容的差异。

git diff HEAD – 文件名 查看本地工作区file文件和本地仓库中最近一次commit该文件的区别 （一般是在不同分支做代码合并的时候用）

– Git仓库 vs Git仓库 ： git diff

git clean 清除工作区中git版本控制的文件，比如临时文件，构建出来的二进制文件 一般用git clean -dxf

git branch 显示本地分支

git branch -r 查看远端所有分支

git branch -a 查看本地和远端的所有分支

git branch xxx 新建分支，但是不切换

git checkout -b 本地分支 origin/远程分支 -》创建本地分支并切换，并且和远端分支关联（前提远端分支是存在的）

上面那一句等于：（前提远端分支是存在的）

创建 ：git branch 本地分支 ->

然后切换：git checkout 本地分支 ->

建立联系：git push –set-upstream 远程主机名(一般是origin) 远程分支名

建立联系是为了pull，push的时候，不用去额外指定参数了，本地的aa分支和远端的aa分支关联了，那么切换到本地分支aa做的修改，想要push到远端，不指定远端分支的话，git push 默认就推到远端aa上了。一般我们理想的也是这样，本地和远端一一对应

git checkout xx 切换分支

git status 本次修改（新增、删除、修改）中涉及到哪些文件，同时也可以看到已经存入暂存区中发生修改变更的文件，便于检查具体修改了哪些文件，以免出现疏漏

git remote -v 可以查看本地仓库连接的远程仓库是啥

git branch -d 本地分支 -> 删除本地分支 （注意不能此时在本地分支去删除本地分支），这里的删除必须保证要删除的分支的修改已经合并了

如果说想强制删，不管有没有修改合并，就用git branch -D 本地分支

git branch -d -r origin/远端分支 ->删除远端分支

远端分支删完之后还必须推送上去才行 : git push origin :远端分支

git blame file可以追溯某个文件的修改记录，也就是能看到某个文件被谁修改了，是哪一笔commit，找到owner

git remote prune origin

在远端创建新分支之后，本地git branch -r 看不到创建的分支，这时候可以这样：

  • git remote update origin：这个子命令会更新本地代码库中远程分支的信息。它会拉取远程仓库的所有分支信息，并将它们存储到本地的.git/refs/remotes/origin目录下。如果本地代码库中没有某些远程分支，它们也会被创建出来。
  • git remote update origin –prune：这个子命令在更新远程分支信息的同时，会删除本地已经不存在于远程仓库中的分支。这可以帮助你保持本地代码库的干净和整洁。

需要注意的是，这个命令中的origin指的是远程仓库的名称。如果你的代码库中有多个远程仓库，你可以通过修改origin来指定要更新的远程仓库。

git checkout – . 相当于把我修改的但是还没有add的所有文件全部回退到最修改之前的样子。命令用来检出仓库中的版本文件，舍弃工作目录中的更改。 可以简化为git checkout . （注意只能对与所有文件 .的时候才能这么简化)

git checkout – file 文件表示 退回没add之前的,（对文件中内容的操作，无法对添加文件、删除文件起作用） 等于 git restore file（不包括对文件自身的操作，如添加文件、删除文件）

git restore –staged 将暂存区的修改重新放回工作区,也就是add之后没commit的恢复到add之前状态（包括对文件自身的操作，如添加文件、删除文件） **等价于 git reset HEAD file ，**比如说新添加了文件，add之后不想要了，想撤销这个add的新添加文件，可以用这俩命令，或者说原来有的文件（工作区是干净的，也就是远端已有的文件），本地现在给删了。如果正常add，提交，push之后远端这个文件也没了，现在的你删除之后，又不想删了，这个文件还是想留着 同样可以用这俩命令

git checkout HEAD – file 文件表示 退回add之后但是没有commit的

管理项目代码：三种方式

1、开发不同的需求，代码保存在本地的一个文件夹中，我们拉不同的远程分支和本地分支，一个分支对应只去开发一件事。开发不同的事情我们需要来回git checkout xx去切换分支开发

2、开发不同的需求，创建不同的文件夹，好比我们本地存多份项目代码，每一份项目代码中只用去拉我们自己的开发分支，专注开发，一份代码对应开发一件事情（推荐）

3、利用worktree

工作流：

1、先本地clone代码

之后每天来先同步远端，本地git pull,（git pull 是fetch和merge的组合），建议用 git pull -rebase

2、然后先再远端智研直接创建远端分支在对应的标签下：bugfix，feature，feature_dev

不建议先git checkout -b 本地branch 把本地分支创建好之后 直接 git push origin <本地分支名>:<远程分支名> 直接创建远端分支 （如果已经切换到了对应本地分支，那么不需要指明<本地分支名>: 可以直接git push origin 远端分支）

3、本地同步分支：

git fetch ->把远端创建的分支信息同步到本地上来，，（和git pull不一样，git pull是拉代码）

git checkout -b 本地分支名 origin/远端分支名 -> 本地创建分支，切换到创建的分支，本地分支并且和远端的分支关联 （建议本地和远端的名字一样）

4、基于本地开发

git add 把工作区文件提交到暂存区

git commit -m “xx” 把暂存区的改动提交到了本地代码仓库的分支上（就是提交到了本地分支上）

git push origin xx:yy 把本地分支xx上的 提交到远程仓库 分支yy上，origin是远程主机名，一般默认都是这个

如果本地分支和远端分支已经建立连接，并且本次push操作就是想推到对应的远端的分支上，并且远程分支已经存在，并且你在本地分支上执行了 checkout 操作切换到了你要推送的本地分支那就直接可以 git push 去推 。（建议指明分支名）git push 该命令会将当前分支推送到与之关联的远程分支上。
