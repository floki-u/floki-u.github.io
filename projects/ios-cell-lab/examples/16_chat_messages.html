📦 核心实现 — 倒置列表 + 键盘联动

聊天 UI 最经典的难题：消息按时间正序，但 UI 从底部插入。微信的解法是用 transform 倒置 tableView。

1️⃣ 经典做法：倒置 TableView（微信同款）

- (void)setupChatList { _tableView = [[UITableView alloc] initWithFrame:self.view.bounds]; // ⭐⭐⭐ 核心黑魔法：上下翻转整个 tableView _tableView.transform = CGAffineTransformMakeScale(1, -1); // 每个 cell 也要再翻转回来 // 在 cellForRow 里：cell.contentView.transform = CGAffineTransformMakeScale(1, -1); [self.view addSubview:_tableView]; } // 数据源：倒序展示 - (UITableViewCell *)tableView:(UITableView *)tv cellForRowAtIndexPath:(NSIndexPath *)ip { ChatBubbleCell *cell = [tv dequeueReusableCellWithIdentifier:@"chat"]; // ⭐ 反过来取数据：最新消息 = messages[0] = 显示在最底部 [cell configureWithMessage:self.messages[ip.row]]; // ⭐ 翻转回来 cell.contentView.transform = CGAffineTransformMakeScale(1, -1); return cell; } // 收到新消息 = insert 到 0，自动出现在底部 - (void)receiveNewMessage:(Message *)msg { [self.messages insertObject:msg atIndex:0]; [self.tableView insertRowsAtIndexPaths:@[[NSIndexPath indexPathForRow:0 inSection:0]] withRowAnimation:UITableViewRowAnimationTop]; // ⭐ 因为 transform 倒了，Top 动画其实是从下往上滑入 }
为什么倒置？
聊天有三大需求：
1. 新消息从底部出现 — 倒置后 insert(0) 就在底部
2. 初始进入定位最新消息 — 倒置后 contentOffset = 0 就是最新
3. 加载历史时不跳变 — 倒置后历史在底部 append，contentSize 增加但 offset 不变
用倒置一行解决三件事，是微信、QQ、WhatsApp 的共同选择。

2️⃣ 现代做法：UICollectionView + Inverted Layout（更优雅）

// iOS 13+ Compositional Layout 也可以做，更可控 - (UICollectionViewLayout *)makeChatLayout { UICollectionViewCompositionalLayoutConfiguration *cfg = [UICollectionViewCompositionalLayoutConfiguration new]; cfg.scrollDirection = UICollectionViewScrollDirectionVertical; UICollectionViewCompositionalLayout *layout = [UICollectionViewCompositionalLayout layoutWithSection:[self messageSection] configuration:cfg]; return layout; } // CollectionView 的好处：item 可以"贴边"显示，不需要倒转技巧 // 用 contentInset.top = view.height - estimatedContentHeight 顶到底部 // 配合 Diffable DataSource 自动处理插入动画

3️⃣ 键盘联动 — 输入框跟随键盘上移

// 监听键盘通知 - (void)viewDidLoad { [super viewDidLoad]; [[NSNotificationCenter defaultCenter] addObserver:self selector:@selector(keyboardWillChange:) name:UIKeyboardWillChangeFrameNotification object:nil]; } - (void)keyboardWillChange:(NSNotification *)note { // ⭐ 取出键盘最终 frame CGRect endFrame = [note.userInfo[UIKeyboardFrameEndUserInfoKey] CGRectValue]; // ⭐ 取出动画时长和曲线（必须用键盘自带的，否则不同步） NSTimeInterval duration = [note.userInfo[UIKeyboardAnimationDurationUserInfoKey] doubleValue]; UIViewAnimationCurve curve = [note.userInfo[UIKeyboardAnimationCurveUserInfoKey] integerValue]; CGFloat bottomInset = self.view.bounds.size.height - endFrame.origin.y; [UIView animateWithDuration:duration delay:0 options:(curve << 16) // ⭐ 转换成 options 参数 animations:^{ self.inputBarBottomConstraint.constant = -bottomInset; [self.view layoutIfNeeded]; } completion:nil]; }

4️⃣ 性能：万条历史消息瞬间滚到底部

// ⭐ 关键：不要直接 scrollToRow，会触发遍历计算高度 - (void)scrollToBottomImmediately { // 倒置 tableView 滚到底 = 滚到 contentOffset.y = 0 [self.tableView setContentOffset:CGPointZero animated:NO]; } // ⭐ 高度全部预计算（在子线程，消息入库时就算好） @interface Message : NSObject @property (nonatomic, assign) CGFloat cachedBubbleHeight; // 子线程预算 @end - (CGFloat)tableView:(UITableView *)tv heightForRowAtIndexPath:(NSIndexPath *)ip { return self.messages[ip.row].cachedBubbleHeight; // O(1) 查询 }

⚖️ 反例 vs 正例

❌ 反例：正向列表 + 滚到底

每次插入新消息都 scrollToBottom
→ 估算 contentSize 触发遍历
→ 万条消息时卡 200ms+
→ 加载历史消息时 contentOffset 跳变

✅ 正例：倒置 + insert(0)

insert(0) 自动在底部出现
→ 加载历史 = append 到末尾，contentOffset 不变
→ 进入聊天 contentOffset = 0 即最新
→ 万条消息瞬间响应

🎓 可借鉴的聊天 UI 创新

借鉴 1：iMessage 的"消息合并尾巴"
连续消息只在最后一条画"尾巴"（border-radius 不对称）。视觉上把"一段话"聚合成一个语义单元。
iOS 17+ 系统的 messages framework 直接提供这个能力，UIListContentConfiguration 也有类似的 grouping。
借鉴 2：Telegram 的"棋盘背景"
不是为了好看，是为了让深色文字气泡和浅色文字气泡在同一背景上都有足够对比度。
借鉴 3：微信的"输入中..." 状态
对方在敲键盘时，你看到一个流动的"...". 这个微反馈让对话不冷，是 IM 必备能力。
实现：发送 typing 信令，定时器在 3 秒无更新时自动消失。
借鉴 4：长按消息的菜单
iMessage 的 Tapback（emoji 反应）→ 微信沿用
Telegram 的快速回复 / 引用 → 几乎所有 IM 都跟进
长按 = 进入"更多动作" 已成全平台心智。
借鉴 5：iMessage 的"朗读"和"激光"特效
普通文字消息可以发"激光""气球""烟花"等动画特效。
这是把"无聊的文字消息"变成"情绪载体"的设计哲学，可以借鉴用在节日彩蛋上。
