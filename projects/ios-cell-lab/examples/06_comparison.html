6️⃣ 反例 vs 正例 完整对比

同一个视觉效果，不同写法导致的性能差异巨大。视觉一样，性能差 5~10 倍。 这一页是前面所有内容的速查表，写代码 / 面试前看一遍。

❌ 反例 1：cornerRadius + clipsToBounds

视觉对，但每帧触发离屏渲染
头
avatar.layer.cornerRadius = 30;
avatar.clipsToBounds = YES;

// → Color Off-screen 黄色块
// → 100 个头像 = 100 次离屏

✅ 正例 1：子线程预切圆图

视觉一样，0 离屏
头
dispatch_async(global, ^{
  UIImage *circle =
    [src circleImageWithSize:size];
  dispatch_async(main, ^{
    avatar.image = circle;
  });
});
// avatar 不需要任何 cornerRadius

❌ 反例 2：阴影不设 shadowPath

系统按 alpha 通道推算，每帧都做
复杂卡片
view.layer.shadowColor =
  [UIColor blackColor].CGColor;
view.layer.shadowOpacity = 0.15;
view.layer.shadowRadius = 8;
// 没设 shadowPath
// → 每帧都要算阴影形状 → 离屏

✅ 正例 2：显式 shadowPath

告诉系统阴影形状，省去推算
复杂卡片
view.layer.shadowColor =
  [UIColor blackColor].CGColor;
view.layer.shadowOpacity = 0.15;
view.layer.shadowRadius = 8;
// ⭐ 显式给 path
view.layer.shadowPath =
  [UIBezierPath
    bezierPathWithRoundedRect:bounds
                cornerRadius:12].CGPath;

❌ 反例 3：cell 开 shouldRasterize

复用即失效，反向优化
第 1 次配置 缓存 MISS
复用，数据变了 缓存 MISS
复用，数据又变 缓存 MISS 
// ❌ 千万不要这么写
cell.layer.shouldRasterize = YES;
// cell 复用 → 内容变 → 缓存失效
// → 每帧重画 + 多了一次缓存写入
// → 比不开还慢

✅ 正例 3：HeroCard 动画期间开

layer 不变，缓存命中率 100%
🎯
静态卡片 + transform 动画
layer 内容不变 → 缓存全命中 
heroCard.layer.shouldRasterize = YES;
[UIView animateWithDuration:0.6
                 animations:^{
  heroCard.transform = identity;
} completion:^(BOOL done) {
  // ⭐ 动画结束立刻关
  heroCard.layer.shouldRasterize = NO;
}];

❌ 反例 4：多层 view 叠加做装饰

N 个 subview，N 次混合，N 次离屏
广告卡片
[contentView addSubview:gradientView];
[contentView addSubview:circle1];
[contentView addSubview:circle2];
[contentView addSubview:label];
// → 4 次混合，2 次圆形离屏

✅ 正例 4：离线渲染成 UIImage

cell 上只 1 个 UIImageView
广告卡片
// ⭐ 子线程一次画完 → UIImage
UIImage *bg = [AdBackgroundRenderer
  backgroundImageForSize:size
                  theme:vm.theme];
imageView.image = bg;
// → 1 个 UIImageView, 0 离屏

❌ 反例 5：heightForRow 现算

10000 行就是 10000 次 layout
- (CGFloat)tableView:tv
   heightForRow:(NSIndexPath *)ip {
  MessageCell *cell =
    [[MessageCell alloc] init];
  [cell configureWith:data];
  // ❌ 用 systemLayoutSize 现算
  return [cell.contentView
    systemLayoutSizeFittingSize:...
  ].height;
}
// reloadData → 全部行算一遍 → 卡顿

✅ 正例 5：子线程预算 + 缓存

heightForRow 是 O(1) 查表
// 子线程预算所有 cell 的高度
dispatch_async(global, ^{
  for (Message *m in messages) {
    MessageViewModel *vm = ...;
    [vm prepareLayoutIfNeeded];
  }
  dispatch_async(main, ^{
    [tableView reloadData];
  });
});

- (CGFloat)tableView:tv heightForRow:ip {
  return vms[ip.row].cachedHeight;
}

❌ 反例 6：主线程加载大图

主线程解码 4MB 图 = 20+ms 卡顿
UIImage *image =
  [UIImage imageNamed:@"big_4mb"];
imageView.image = image;
// ❌ imageNamed 是懒解码
// 第一次上屏时主线程解码
// → 一帧时间 20+ms

✅ 正例 6：子线程强制解码

主线程只做 setImage
dispatch_async(global, ^{
  UIImage *raw =
    [UIImage imageWithContentsOfFile:p];
  // ⭐ 子线程强制解码
  UIImage *decoded =
    [raw decodedImage];
  dispatch_async(main, ^{
    imageView.image = decoded;
  });
});
// SDWebImage 默认这么做

❌ 反例 7：没写 prepareForReuse

头像错乱、红点不消失等经典 bug
- (void)configureWith:(Message *)m {
  [self.avatarView
    sd_setImageWithURL:m.url];

  if (m.unreadCount > 0) {
    self.badgeView.hidden = NO;
  }
  // ❌ 没 else
  // 复用时旧红点不消失
}

✅ 正例 7：prepareForReuse 重置

复用前自动清理所有状态
- (void)prepareForReuse {
  [super prepareForReuse];
  // 1. 取消异步任务
  [self.avatarView
    sd_cancelCurrentImageLoad];
  // 2. 清空 UI 状态
  self.avatarView.image = nil;
  self.badgeView.hidden = YES;
  // 3. 停止动画
  [self.indicator stopAnimating];
}
