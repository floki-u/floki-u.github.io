4️⃣ AdCell（复杂装饰背景：离线渲染最佳实践）

广告 cell 经常有复杂的装饰背景（渐变 + 装饰圆 + 光晕）。 这种场景千万不要堆 N 层 view + 透明度叠加， 最佳实践是整个背景一次性画成一张 UIImage，cell 上只贴 UIImageView。 本节告诉你为什么这比光栅化更优。

💡 核心思想：能合并的层就合并

❌ 反例：多层 view 叠加
[contentView addSubview:gradientView];     // 渐变背景
[contentView addSubview:circle1];          // 装饰圆 1
[contentView addSubview:circle2];          // 装饰圆 2
[contentView addSubview:blurView];         // 模糊层
[contentView addSubview:label1];           // 标签
[contentView addSubview:label2];           // 标题

// ❌ 6 个 subview 叠加
// ❌ 装饰圆要 cornerRadius=50 + clipsToBounds
//    → 2 次离屏
// ❌ 半透明叠加 → 多次混合
// ❌ Color Blended Layers 全红
// ❌ Color Off-screen Rendered 大量黄色
✅ 正例：离线渲染成一张 UIImage
// cell 上只有一个 UIImageView
[contentView addSubview:backgroundImageView];

// 把整个背景预渲染成 UIImage
UIImage *bg = [AdBackgroundRenderer
  backgroundImageForSize:size
                  theme:@"purple"];
backgroundImageView.image = bg;

// 标签直接叠在 imageView 上
[backgroundImageView addSubview:titleLabel];
[backgroundImageView addSubview:descLabel];

// ✅ 1 个 UIImageView + 2 个 label
// ✅ 0 离屏（图本身就是圆角的）
// ✅ 0 混合（全部 opaque）
// ✅ 同主题广告共用一张 UIImage

🛠️ AdBackgroundRenderer：离线渲染器实现

用 UIGraphicsImageRenderer 在子线程一次画完所有装饰
@interface AdBackgroundRenderer : NSObject
+ (UIImage *)backgroundImageForSize:(CGSize)size
                              theme:(NSString *)theme;
@end

@implementation AdBackgroundRenderer

// ⭐ NSCache 缓存，跨 cell 复用
+ (NSCache *)imageCache {
  static NSCache *cache;
  static dispatch_once_t once;
  dispatch_once(&once, ^{
    cache = [[NSCache alloc] init];
    cache.countLimit = 20;
  });
  return cache;
}

+ (UIImage *)backgroundImageForSize:(CGSize)size
                              theme:(NSString *)theme {
  // 1. 命中缓存直接返回
  NSString *key = [NSString stringWithFormat:@"%@_%@",
                                                theme, NSStringFromCGSize(size)];
  UIImage *cached = [[self imageCache] objectForKey:key];
  if (cached) return cached;

  // 2. UIGraphicsImageRenderer 一次画完
  UIGraphicsImageRendererFormat *fmt = [UIGraphicsImageRendererFormat preferredFormat];
  fmt.opaque = YES;  // ✅ 不透明
  UIGraphicsImageRenderer *renderer =
    [[UIGraphicsImageRenderer alloc] initWithSize:size format:fmt];

  UIImage *image = [renderer imageWithActions:^(UIGraphicsImageRendererContext *ctx) {
    CGContextRef c = ctx.CGContext;

    // (1) 圆角矩形裁剪
    UIBezierPath *clip = [UIBezierPath
      bezierPathWithRoundedRect:CGRectMake(0, 0, size.width, size.height)
                  cornerRadius:12];
    [clip addClip];

    // (2) 渐变背景
    CGColorSpaceRef cs = CGColorSpaceCreateDeviceRGB();
    CGFloat colors[] = {
      0.40, 0.49, 0.92, 1.0,   // #667eea
      0.46, 0.29, 0.64, 1.0,   // #764ba2
    };
    CGGradientRef grad = CGGradientCreateWithColorComponents(cs, colors, NULL, 2);
    CGContextDrawLinearGradient(c, grad,
      CGPointMake(0, 0),
      CGPointMake(size.width, size.height), 0);
    CGGradientRelease(grad);
    CGColorSpaceRelease(cs);

    // (3) 装饰圆（右上）
    [[UIColor colorWithWhite:1 alpha:0.2] setFill];
    [[UIBezierPath
      bezierPathWithOvalInRect:CGRectMake(size.width - 150, -50, 200, 200)] fill];

    // (4) 装饰圆（左下）
    [[UIColor colorWithWhite:1 alpha:0.15] setFill];
    [[UIBezierPath
      bezierPathWithOvalInRect:CGRectMake(30, size.height - 70, 100, 100)] fill];
  }];

  // 3. 缓存
  [[self imageCache] setObject:image forKey:key];
  return image;
}

@end
⭐ 关键点： UIGraphicsImageRenderer 是 iOS 10+ 的现代绘图 API， 自动处理 scale、color space、内存管理，比老的 UIGraphicsBeginImageContext 快约 30%。

📦 AdCell.m：极简的 cell 结构

@implementation AdCell

- (instancetype)initWithStyle:... {
  if (self = [super ...]) {
    // ⭐ 整个 cell 的复杂背景 = 1 个 UIImageView
    _backgroundImageView = [[UIImageView alloc] init];
    _backgroundImageView.opaque = YES;
    [self.contentView addSubview:_backgroundImageView];

    // 文字 label 直接叠上去
    _badgeLabel = [self _makeLabel];
    _titleLabel = [self _makeLabel];
    _descLabel  = [self _makeLabel];
    [_backgroundImageView addSubview:_badgeLabel];
    [_backgroundImageView addSubview:_titleLabel];
    [_backgroundImageView addSubview:_descLabel];
  }
  return self;
}

- (void)prepareForReuse {
  [super prepareForReuse];
  self.backgroundImageView.image = nil;
  self.titleLabel.text = nil;
  self.descLabel.text = nil;
}

- (void)configureWithViewModel:(AdViewModel *)vm {
  self.backgroundImageView.frame = self.contentView.bounds;
  self.titleLabel.text = vm.title;
  self.descLabel.text = vm.desc;

  // ⭐ 子线程取背景图（缓存命中时立即返回）
  CGSize size = self.contentView.bounds.size;
  dispatch_async(global_queue, ^{
    UIImage *bg = [AdBackgroundRenderer
      backgroundImageForSize:size theme:vm.theme];
    dispatch_async(main_queue, ^{
      if ([self.viewModel.theme isEqualToString:vm.theme]) {
        self.backgroundImageView.image = bg;
      }
    });
  });
}

@end

🆚 vs 光栅化的本质区别

"画一次缓存"看似一样，但在 cell 场景下差距巨大
维度 shouldRasterize（光栅化） 离线渲染成 UIImage
缓存策略 系统管，100ms 不用就清 自己用 NSCache 管，永久
跨 cell 复用 ❌ 一个 view 一份缓存 ✅ 所有同主题 cell 共用一张图
失效条件 layer 内容变化即失效 完全可控，永不失效
cell 复用场景 ❌ 复用即失效，反向优化 ✅ cell 只是 setImage，0 成本
额外 view 数量 多层 subview 叠加 只需 1 个 UIImageView
混合层数 多层叠加都要混合 1 层不透明图，无混合
🎯 结论： 「复杂装饰 + 内容相对固定 + 在列表中频繁复用」的场景，永远用离线渲染成 UIImage， 不要用光栅化。这是 cell 场景的最佳实践。
